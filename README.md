# Maintainer Desk

Security advisories that answer back. An entry for the Open Agentic Web Challenge, built on the
[Worldwide Agentic Web MVP spec](https://github.com/cognizant-ai-labs/agentic-web/blob/main/docs/worldwide_agentic_web_mvp_spec.md)
(MVP Profile 0.2).

Every scanner alert ends in the same question: does this vulnerability affect my app? Databases
such as OSV say which versions are affected. They do not say when the bug can actually be reached,
which workaround is safe, or whether a backport is coming. That knowledge sits with the
maintainers, and it reaches users as a stream of "is this project affected by CVE-X?" issues.

Maintainer Desk lets maintainers publish that knowledge as a small static agentic website on their
own project domain, and lets developers ask it from a triage page in their own browser:

- **Maintainer desk.** A static site per project: security policy, supported versions, advisories
  with the conditions under which each one applies, a private report form, an OSV feed, and an
  agent network that answers "does this apply to my setup?". The maintainer runs no server and pays
  for no model calls: visitors bring their own key.
- **Triage Desk.** Paste `package.json`, `package-lock.json` or `requirements.txt`. The page asks
  OSV.dev which advisories affect each exact version, reads the desk's own feed for packages that
  publish one, and lists the findings. Its assistant explains them, asks the package's desk (after
  a consent card that names the desk's origin), and proposes an OpenVEX decision that cites its
  source. Nothing is recorded until the visitor applies it. The result downloads as an OpenVEX file.
- **Desk Kit.** `kit/build_desk.mjs` (command line) and `kit.html` (in the browser) turn a
  `desk.json` (policy plus OSV advisories with applicability notes) into a complete, conforming desk.
  Both demo desks are built with it.
- **Spec Checks.** `checks.html` runs the spec's section 6 checks in the browser with the site's own
  runtime: invalid network, undeclared origin, composition cycle, depth limit, call budgets, router
  inheritance and private-context filtering.

`lanternmd` (npm) and `tidecache` (PyPI) are fictional demo projects; their names were free on both
registries on 16 Nov 2026. Every other package and advisory in the demo is real data from OSV.dev.

## How it uses the spec

- **Portable network (section 2).** Each site publishes HOCON (`*.hocon`) and the resolved,
  data-only JSON the browser loads (`*.network.json`), built with the runtime's own parser and
  validator. No includes, substitutions, `demo_mode` or coded tools.
- **Browser execution (section 3).** The patched nsdeploy runtime from the challenge repository
  (`tools/agentify-website/runtime`, unchanged, Apache 2.0) runs every network in the visitor's tab.
- **Peer loading (section 3.2).** The Triage Desk names each desk's exact network URL in its agent's
  `tools`, lists the desk origins in `allowed_peers` with a closed `peer_policy`, and labels them in
  `link_labels`. A desk's network runs in the Triage page's browser, on the visitor's router and key.
- **Why a desk is useful when called (section 3.2 and the reference runtime).** A called network
  gets the request text only: no chat history, no private context, and none of either site's
  `website_*` tools. So the desk keeps the maintainers' notes in its `advisory_notes` agent,
  generated by the kit from the same `desk.json` the page renders. A caller gets grounded answers
  without site tools, and the notes cannot drift from the page.
- **Pluggable inference (section 4).** Default router: hosted Otari with `alibaba/qwen3.8-flash`.
  Any OpenAI-compatible router with CORS works through the AI model settings panel.
- **Writes shown first (section 3.1).** The reference runtime runs `write` actions without a dialog.
  The Triage Desk closes that gap in the site: `propose_vex_statement` only stages a proposal, and
  the visitor applies or discards it with a button. A desk's `draft_private_report` only fills in a
  form; the visitor sends the email from their own mail program.
- **Untrusted peers (section 5).** A desk's answer is data. The Triage Desk refuses to cite a desk
  that was not contacted in the session, labels every statement with its source origin, and never
  lets a desk answer trigger an action.
- **Observable execution (section 5).** The Triage page lists every origin it or its assistant
  contacted, and why.

Live check (local, 16 Nov 2026): the desk's network loaded only after the visitor allowed it, ran
in the caller's browser on the caller's router, and the desk server logged 0 Authorization headers.
See `docs/evidence/live-check-2026-11-16.md`.

## Linked sites

- The Triage Desk calls `<lanternmd base>/lanternmd_security_desk` and
  `<tidecache base>/tidecache_security_desk`. Locally the desks run on the host name `localhost`
  and the Triage Desk on `127.0.0.1`: on one host name the runtime's key cookie would reach the
  other site.
- Before any contact the chat shows a card with the desk's name, its host and the first 140
  characters of the request. **Always allow** skips the card for that host until the page is
  reloaded.
- A request holds a package, a version, an advisory id and a one-line usage question. The assistant
  is told never to include names, emails, repository URLs or code. The runtime does not filter the
  request, so the visitor checks it on the card.
- The desk's network runs in the visitor's browser on the visitor's key, with none of the desk's
  site tools. It answers from the maintainers' published notes. A call costs more tokens than the
  card's estimate.
- Other agentic websites can call the Triage Desk too. They get none of its site tools, so it can
  only point them to its page.

## Run it locally

Node 22 or newer. From this folder:

```bash
node scripts/build_all.mjs --env local --check
```

```bash
node --test "tests/*.test.mjs"
```

```bash
node scripts/serve.mjs sites/triage --port 8080
```

```bash
node scripts/serve.mjs sites/lanternmd-desk --port 8081
```

```bash
node scripts/serve.mjs sites/tidecache-desk --port 8082
```

Open `http://127.0.0.1:8080/`. The findings table works without any key. To use the assistant,
open **AI model settings** and paste a key for your provider (hosted Otari by default). The
assistant sends your messages, and the page data it reads, to that provider. On `localhost` and
`127.0.0.1` the runtime also keeps the key in a cookie, so use a key with a low spending limit, and
afterwards select **Delete setup** and close the tab.

`scripts/serve.mjs` sends the same headers as the `_headers` files: CORS on the public agent files
and the OSV feed, and the required CSP on `runtime/sandbox-worker.js`. It can log each request
(path, Origin, whether an Authorization header came, cookie names; never values) with `--log`.

## Make a desk for your project

In the browser: open `kit.html` on the Triage Desk, paste your `desk.json`, download the zip.
On the command line:

```bash
node kit/build_desk.mjs desks/lanternmd/desk.json --out my-desk --base-url https://security.example.org/
```

Host the folder at that address on any static host with HTTPS. `_headers` (Netlify, Cloudflare
Pages) and `vercel.json` set the headers; GitHub Pages sends `Access-Control-Allow-Origin: *` on
every file by itself, and `.nojekyll` keeps `.well-known/` published.

## Limits

- Static hosting only, with the challenge's patched copy of the nsdeploy runtime.
- The runtime offers every `website_*` tool to every agent of a site; specialists are scoped by
  their instructions only.
- Each partner call runs on the visitor's key: at most 4 per message and 1 per partner.
- A partner that accepts a connection but never answers leaves the chat waiting until reload.
- When a model router sends an error event mid-stream (for example a context overflow), the
  runtime's stream parser skips it and the agent ends with an empty answer. Found in the live check;
  it is in the vendored runtime, which sites must not change.
- Version ranges in `package.json` are checked at their lowest version; paste a lockfile for the
  installed versions. `requirements.txt` lines are checked only when pinned with `==`.
- Everything in the network files, including instructions, is public by design.
